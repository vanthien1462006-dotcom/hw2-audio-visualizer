# TASK_DECOMPOSITION: Concurrent FIFO Audio Visualizer (HW2)

Written for: the developer and the AI agent that will implement HW2 task by task.

## 1. Overview

A small audio player built with Vite and vanilla TypeScript (strict mode), with no runtime dependencies.

- A FIFO queue loads and decodes tracks. At most `maxConcurrent` tasks run at the same time.
- A Web Audio `AnalyserNode` (`fftSize` 512, so 256 frequency bins) draws a spectrum on a `<canvas>` inside a `requestAnimationFrame` loop. The target is 60 fps, and the real value is measured by the user in DevTools.
- Every resource is released: timers, animation frame ids, event listeners, `AbortController`s, `AudioBufferSourceNode`s and the `AudioContext`.
- The sample tracks are WAV files generated by a Node script that has no dependencies.

Commands (from `project-rules.md`):

- `npm run dev` serves on http://localhost:5173.
- `npm run build` runs `tsc && vite build`.
- `npm run preview` serves on http://localhost:4173.
- `npm test` runs `node --test "src/**/*.test.ts"`.

Prerequisite: Node 24 or later can run `.ts` files directly (type stripping). The project was checked with Node v24.14.1.

## 2. Design decisions and open questions

### 2.1 Decisions made in this spec

The user may change any of these before the task that depends on it.

- **D1. Concurrency slot is held until the work settles.** When a running task is cancelled, its slot is not released. The slot is released only when the `work` promise settles. Reason: `decodeAudioData` cannot be aborted, so an early release would let running decodes exceed `maxConcurrent`.
- **D2. Cancelling a loading task.** `cancel()` aborts the task's signal, sets status to `cancelled` and rejects the caller's promise at once with an `AbortError`. When the late decode finishes, its buffer is discarded.
- **D3. Duplicate URLs.** `enqueue()` throws if an entry for the same URL is `queued` or `loading`. After a terminal status (`ready`, `cancelled`, `error`), the same URL may be enqueued again. The new entry replaces the old record.
- **D4. Work failure.** If `work` rejects with a non-abort error, status becomes `error`, the caller's promise rejects with that error, the slot is released and the queue continues.
- **D5. Playback model.** The most recent `ready` track becomes the current track. Play starts it from the beginning, or resumes it when paused. Pause calls `AudioContext.suspend()`. Stop stops the `AudioBufferSourceNode` and disconnects it.
- **D6. Two methods added to the queue for the view.** The brief lists only `enqueue`, `cancel` and `dispose`. The queue view also needs `snapshot()` and `subscribe()`. **Needs user approval before H2-T03.**
- **D7. `maxConcurrent` validation.** It is read from `data-max-concurrent`, which is untrusted. The constructor throws unless it is an integer of at least 1.
- **D8. Reduced motion.** When `(prefers-reduced-motion: reduce)` matches, the visualizer does not start the `requestAnimationFrame` loop. It draws one static baseline frame.

### 2.2 Open questions that block work

- **O1. Types for `node:test` (blocks H2-T06).** `tsconfig.json` has `types: ["vite/client"]` and `include: ["src"]`. `@types/node` is not installed, and project rules allow only `vite` and `typescript`. If a test file imports `node:test`, `npm run build` (`tsc`) fails. Options:
  - A. The user approves `@types/node` as a dev dependency. This is a rule change.
  - B. Exclude `src/**/*.test.ts` from the `tsc` build. Tests run with Node type stripping and are not type-checked.
  - Recommendation: B, because it adds no dependency. The cost is that tests are not type-checked.

## 4. Contract (committed in H2-T03 as `src/contract.ts`)

```ts
export type AudioTask = (trackUrl: string, signal: AbortSignal) => Promise<AudioBuffer>;

export interface AudioTaskQueueOptions {
  readonly maxConcurrent: number;
  readonly work: AudioTask;
}

export interface VisualizerOptions {
  readonly canvas: HTMLCanvasElement;
  readonly analyser: AnalyserNode;
}

export type TrackStatus = 'queued' | 'loading' | 'ready' | 'cancelled' | 'error';

export interface QueueEntry {
  readonly trackUrl: string;
  readonly status: TrackStatus;
}
```

Class `AudioTaskQueue` (in `src/audio-task-queue.ts`):

```ts
export class AudioTaskQueue {
  constructor(options: AudioTaskQueueOptions);
  enqueue(trackUrl: string): Promise<AudioBuffer>;
  cancel(trackUrl: string): boolean;   // true if a queued or loading entry was cancelled
  dispose(): void;
  snapshot(): readonly QueueEntry[];                                          // D6
  subscribe(listener: (entries: readonly QueueEntry[]) => void): () => void;  // D6, returns unsubscribe
}
```

Class `AudioEngine` (in `src/audio-engine.ts`):

```ts
export class AudioEngine {
  constructor();
  load(trackUrl: string, signal: AbortSignal): Promise<AudioBuffer>; // matches AudioTask
  play(buffer: AudioBuffer): void;   // stops the previous source first
  pause(): void;                     // AudioContext.suspend()
  resume(): void;                    // AudioContext.resume()
  stop(): void;
  getAnalyser(): AnalyserNode;       // fftSize 512
  dispose(): void;
}
```

Class `Visualizer` (in `src/visualizer.ts`):

```ts
export class Visualizer {
  constructor(options: VisualizerOptions);
  start(): void;   // idempotent
  stop(): void;    // cancels the animation frame id
  dispose(): void; // calls stop()
}
```

Helper types for untrusted input: parameters that come from the DOM or from `data-*` attributes are typed as `unknown` at the boundary and narrowed before use.

## 5. Behavior rules

### 5.1 Queue (`AudioTaskQueue`)

1. Entries start in FIFO order: the first entry enqueued is the first started.
2. The number of running tasks never exceeds `maxConcurrent`. A task counts as running until its `work` promise settles (D1).
3. A task cancelled while still `queued` never calls `work`.
4. A task cancelled while `loading` has its `signal.aborted` set to `true`. Its result is discarded when it settles (D2).
5. `enqueue()` resolves with the `AudioBuffer` when status becomes `ready`.
6. `enqueue()` rejects with an `AbortError` when the task is cancelled, or when the queue is disposed.
7. After `dispose()`, nothing new starts, `enqueue()` throws, and `cancel()` returns `false`. Calling `dispose()` twice is safe.

### 5.2 Track URLs (`resolveTrackUrl`)

Track URLs are untrusted (they come from `data-track-url`). `resolveTrackUrl(input: unknown, origin: string): string` must:

- Throw if `input` is not a string.
- Resolve `input` against `origin` with `new URL`.
- Throw unless the resolved origin equals `origin`.
- Throw unless the normalized pathname starts with `/assets/tracks/`.
- Throw if the URL has a query or a hash.
- Return the pathname on success.

Examples that must be rejected: `https://other.example/assets/tracks/a.wav`, `//other.example/assets/tracks/a.wav`, `javascript:alert(1)`, `/assets/other/a.wav`, `/assets/tracks/../secret.wav`, `/assets/tracks/%2e%2e/secret.wav`.

### 5.3 Engine (`AudioEngine`)

1. `load()` calls `resolveTrackUrl` before any `fetch`. A rejected URL never reaches the network.
2. `load()` passes `signal` to `fetch`. It checks `signal.aborted` after the fetch and again after `decodeAudioData`, because decode cannot be cancelled. If the signal is aborted, it throws `AbortError` and drops the buffer.
3. The `AudioContext` is created once, lazily, on first use. `dispose()` closes it.
4. `play()` stops and disconnects the previous `AudioBufferSourceNode` and clears its `onended` handler before creating a new one.
5. The graph is `source -> analyser -> destination`. The analyser uses `fftSize` 512.
6. `dispose()` stops the source, disconnects the nodes and closes the context. It is idempotent.

### 5.4 Visualizer (`Visualizer`)

1. The constructor preallocates `Uint8Array(analyser.frequencyBinCount)` and `Float32Array(BAR_COUNT)`. The frame function allocates nothing.
2. The frame function does not read layout (`offsetWidth`, `getBoundingClientRect`). Canvas size comes from the `width` and `height` attributes in `index.html`.
3. The bar color is read once in `start()` from a CSS custom property through `getComputedStyle`. It is never hard-coded.
4. Each frame calls `getByteFrequencyData`, then `binsToBars`, then draws, and schedules the next `requestAnimationFrame`.
5. `stop()` calls `cancelAnimationFrame` and resets the stored id to 0.
6. Under `prefers-reduced-motion: reduce`, no loop starts (D8).

### 5.5 Spectrum conversion (`binsToBars`)

- Pure function. It writes into a preallocated `Float32Array` of length `BAR_COUNT` and returns nothing.
- Each output value is in the range 0 to 1.
- Empty input gives all zeros.
